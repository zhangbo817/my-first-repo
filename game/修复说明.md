## 二、改了什么（`game.c`）

### 1. 加了一层平台适配（约 180 行，逻辑层一行没动）

| 功能 | 原实现（POSIX） | Windows 实现 |
|------|----------------|--------------|
| 计时 | `clock_gettime(CLOCK_MONOTONIC)` | `QueryPerformanceCounter` |
| 等待 | `usleep` | `Sleep` |
| 终端尺寸 | `ioctl(TIOCGWINSZ)` | `GetConsoleScreenBufferInfo` |
| 输入 | raw 模式 + `select`/`read` | `ReadConsoleInputW` 事件队列 |
| 颜色 | ANSI 转义 | 打开 `ENABLE_VIRTUAL_TERMINAL_PROCESSING` |
| 中文 | UTF-8 直出 | `SetConsoleOutputCP(CP_UTF8)`，退出还原 |

Linux / macOS 的原有实现全部保留在 `#else` 分支里，原来的
`gcc -std=c11 -O2 -Wall -Wextra -o game game.c -lm` 依然可用。

### 2. 顺手修的逻辑问题

- **按键边沿**：`applyKey()` 只在"刚按下"时置 `edge[]`。Windows 靠 key-up 判定，
  POSIX 靠 240ms 时间窗过滤终端重复字节 → 按住任何键都不会再连点。
- **Esc 超时丢弃**：60ms 内等不到 `[X` 就丢掉这个 Esc，不再吞后续按键。
- **方向键**：抽成 `applyArrow()`，Windows 用 `VK_UP/DOWN/LEFT/RIGHT`，POSIX 仍解析 `ESC [ X`。
- **宽度预算**：`tw - (PANEL_W + 7)`（地图 + 4 列分隔 + 最宽 36 列面板 + 1 列余量）。
- **窗口实时重排**：每帧重读终端尺寸，拖动窗口不再错位。
- **空机库防护**：`idx = (jetCount > 0) ? ... : -1`，`jetArt(-1)` 本来就画默认外形。
- **融合除零**：`G.tab == 2 && jetCount > 1`。
- **Ctrl+C**：Windows 下不再粗暴杀进程，走正常退出并还原控制台。
- **`--frames N`**：新增的自动化开关（跑 N 帧后自动退出），方便无头验证，不影响正常玩。

## 四、怎么跑

```bat
:: 编译（自动找 MSVC，找不到就用 gcc）
build.bat

:: 正常玩（从第 1 关开始，30 关 + 最终 BOSS）
game.exe

:: 其他
game.exe --selftest 30000     :: 无头自测
game.exe --snapshot           :: 输出一帧纯文本画面
game.exe --jetlab             :: 枚举 256 种飞机图纸
game.exe --frames 60          :: 跑 60 帧后自动退出（自动化验证用）
```

操作：`WASD` 移动，`J/L` 转瞄准，`空格` 切换持续开火，`C` 冲刺，
`Tab` 切面板，`↑↓` 选条目，`Enter` 购买/出战/组装，`B` 组装，`G` 随机搭建，
`F` 融合，`1~9` 切机体，`R` 重开，`X` 退出。

> 建议终端 **≥ 100 列 × 24 行**。游戏会自动适应窗口，但太窄会挤。

## 五、看过但**故意没改**的地方

- **经济偏紧**：自测里 30 关打完只剩 5 金币。这是数值设计，不是 bug。
- **贯穿弹的 `hitMask` 只有 32 位**：敌人数组 160 槽，索引 ≥32 时同一发弹可能重复命中。
  实际同屏敌人上限 24，索引复用后很难越过 32，暂时不改（要改就把掩码扩成 5×32 位）。
- **撞到敌人 = 同归于尽**：爆炸式设计，一撞敌人就消失并计入过关数。保持原样。
- **只能从第 1 关打**：原始设定，没有跳关入口。
